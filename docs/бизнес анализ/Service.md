# User Story

## Связывание с модификаторами

**Верхнеуровневый обзор:** как администратор я хочу привязать к услуге модификаторы, чтобы пользователь мог выбирать их значения при оформлении заказа.

**Роль:** администратор.

**Предусловие:** администратор открыл интерфейс создания или редактирования услуги и перешел к привязке модификаторов.

**Бизнес-правила:**

- Привязка модификаторов доступна при создании и редактировании услуги.
- Привязка модификаторов к услуге необязательна.
- К услуге можно привязать несколько существующих модификаторов.
- Каждый привязанный модификатор должен содержать хотя бы одно выбранное значение.
- Для каждого привязанного модификатора определяется, обязателен ли его выбор пользователем.
- Добавочная стоимость обязательна для каждого выбранного значения модификатора и учитывается в конечной стоимости услуги, если пользователь выбрал это значение.

**Основной сценарий:**

1. (№м) Администратор выбирает модификатор из списка доступных модификаторов.
2. Система отображает значения выбранного модификатора.
3. Администратор выбирает одно или несколько значений модификатора, доступных для данной услуги.
	1. `Alt.` Выбор всех значений
4. (№п) Администратор указывает, является ли выбор модификатора обязательным.
5. Администратор указывает добавочную стоимость для каждого выбранного значения модификатора.
6. Система привязывает к услуге выбранный модификатор с выбранными значениями.
7. Администратор завершает настройку.
	1. `Alt.` Добавление очередного модификатора

Критерии приемки: к услуге привязан хотя бы один модификатор; для каждого привязанного модификатора указаны хотя бы одно выбранное значение, признак обязательности выбора и добавочная стоимость каждого выбранного значения; добавочная стоимость выбранного пользователем значения учитывается в конечной стоимости услуги.

**Выбор всех значений:**

1. Администратор выбирает все значения модификатора.
2. Возврат к пункту №п **основного сценария**.

Критерии приемки: для привязываемого модификатора выбраны все его значения.

**Добавление очередного модификатора:**

1. Администратор инициирует добавление очередного модификатора.
2. Возврат к пункту №м **основного сценария**.

Критерии приемки: администратор вернулся к выбору модификатора; ранее добавленные модификаторы сохранены в составе услуги.

## Привязка категории

**Верхнеуровневый обзор:** как администратор я хочу назначить услуге категории, чтобы использовать их для фильтрации услуг.

**Роль:** администратор.

**Предусловие:** администратор открыл интерфейс создания или редактирования услуги и перешел к привязке категорий.

**Бизнес-правила:**

- Привязка категорий доступна при создании и редактировании услуги.
- Услуге должна быть назначена хотя бы одна категория.
- Услуге можно назначить несколько категорий.
- Услуге могут быть назначены либо семантические категории, либо категория «Другое».

**Основной сценарий:**

1. Система отображает доступные категории услуги.
2. Администратор выбирает одну или несколько категорий услуги.
3. Система назначает услуге выбранные категории.
4. Администратор завершает настройку.

Критерии приемки: услуге назначены одна или несколько выбранных категорий; категория «Другое» не назначена одновременно с семантическими категориями.
## Переключение видимости в подборке у клиента

**Верхнеуровневый обзор:** как администратор я хочу переключать видимость услуги в клиентской подборке, чтобы управлять её доступностью для клиента без удаления из системы.

**Роль:** администратор.

**Предусловие:** администратор открыл интерфейс управления услугами.

**Бизнес-правила:**

- Переключение видимости не удаляет услугу из системы.
- Статус отображения услуги может иметь значение `visible` или `hidden`.
- При создании услуги система присваивает ей статус отображения `visible`.
- Услуга со статусом отображения `visible` отображается в клиентской подборке услуг.
- Услуга со статусом отображения `hidden` не отображается в клиентской подборке услуг.

**Основной сценарий:**

1. Администратор выбирает услугу.
2. Система отображает текущий статус отображения услуги.
3. Администратор переключает статус отображения услуги между `visible` и `hidden`.
4. Администратор сохраняет изменение.
5. Система обновляет статус отображения услуги.
6. Система добавляет услугу в клиентскую подборку при статусе `visible` или исключает из неё при статусе `hidden`.

Критерии приемки: статус отображения услуги переключен на противоположный; услуга со статусом `visible` отображается в клиентской подборке; услуга со статусом `hidden` не отображается в клиентской подборке; услуга не удалена из системы.

# Сущности

# Услуга

Сущность услуги для любых типов услуг.

Статусная модель отображения:

1. `visible` — услуга отображается в клиентской подборке.
2. `hidden` — услуга не отображается в клиентской подборке.

## Категория услуги

Услуге можно назначить несколько категорий, например: _платья_, _нижняя одежда_, _футболки_, _украшения_.

Каждой услуге **обязательно** должна быть присвоена **хотя бы одна** категория. Если услуге невозможно присвоить какую-либо семантическую категорию, то может использоваться категория **"Другое"**.

## Результат выполнения услуги

В результате выполнения услуги **ВСЕГДА** в системе должна фиксироваться некая сущность.
Для этой сущности **должна** быть указана конечная стоимость. 

# Механики

## Конечная стоимость

Конечная стоимость рассчитывается по следующей формуле:

$$
\begin{aligned}
P = wp + mp_{i} \\ \\
\text{where: } \\
& wp      && \text{базовая стоимость услуги} \\
& mp_{i} = 0 && \text{сумма стоимости выбранных значений модификаторов} \\
\end{aligned}
$$

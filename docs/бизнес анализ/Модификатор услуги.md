# User Story

## Создание\редактирование модификатора

**Верхнеуровневый обзор:** как администратор я хочу создать или изменить модификатор и его значения, чтобы использовать их при настройке услуги.

**Роль:** администратор.

**Предусловие:** администратор открыл интерфейс создания или редактирования модификатора услуги.

**Бизнес-правила:**

- Название модификатора обязательно и не должно превышать 250 символов.
- Описание модификатора необязательно и не должно превышать 1500 символов.
- Модификатор должен содержать хотя бы одно значение.
- Название значения обязательно, не должно превышать 250 символов и должно быть уникальным в рамках модификатора.
- Описание значения необязательно и не должно превышать 1500 символов.
- Изображение значения необязательно. При его отсутствии данные изображения остаются пустыми.
- При редактировании администратор может изменить любое сочетание полей модификатора и его значений. Данные, которые администратор не изменил, сохраняются без изменений.
- Удаление значения подчиняется [[Общие бизнес-правила#Подтверждение удаления|общему правилу подтверждения удаления]].

**Основной сценарий:**

1. При создании администратор указывает название модификатора; при редактировании изменяет его при необходимости.
2. Администратор указывает или изменяет описание модификатора при необходимости.
3. (№ж) Администратор инициирует сценарий **Ввод информации о значении** для создания значения;
	1. `Alt.` Администратор инициирует сценарий **Ввод информации о значении** для изменения значения
	2. `Alt.` Администратор инициирует сценарий **Удаление значения**
4. (№з) Администратор завершает настройку значений.
	1. `Alt.` Возврат к пункту №ж **текущего сценария**
5. Администратор сохраняет модификатор.
6. Система создает или обновляет модификатор услуги.

Критерии приемки: модификатор создан или обновлен с указанными названием, описанием при его наличии и значениями; модификатор содержит хотя бы одно значение; при редактировании данные, которые администратор не изменил, сохранены без изменений.

**Ввод информации о значении:**

1. Администратор указывает название значения.
2. Администратор указывает описание значения при необходимости.
3. Администратор загружает изображение значения при необходимости.
4. Возврат к пункту №з **основного сценария**.

Критерии приемки: значение с указанным названием, описанием при его наличии и изображением при его наличии добавлено или обновлено; при отсутствии изображения данные изображения остаются пустыми.

**Удаление значения:**

1. Администратор выбирает значение модификатора.
2. Администратор подтверждает удаление.
3. Система удаляет выбранное значение.
4. Возврат к пункту №з **основного сценария**.

Критерии приемки: выбранное значение удалено из модификатора; после сохранения модификатор содержит хотя бы одно значение.

## Удаление модификатора

**Верхнеуровневый обзор:** как администратор я хочу удалить модификатор, чтобы его больше нельзя было добавлять к услугам.

**Роль:** администратор.

**Предусловие:** администратор открыл список модификаторов; в списке есть удаляемый модификатор.

**Бизнес-правила:**

- Удаление модификатора подчиняется [[Общие бизнес-правила#Подтверждение удаления|общему правилу подтверждения удаления]].
- При удалении модификатора система каскадно удаляет все его связи с услугами, включая настройки выбранных значений, обязательности выбора и добавочной стоимости. Связанные услуги не удаляются.
- Модификатор и его значения удаляются из системы.

**Основной сценарий:**

1. (№з) Администратор выбирает модификатор.
2. Администратор запрашивает удаление модификатора.
3. Система запрашивает подтверждение удаления.
4. Администратор подтверждает удаление.
	1. `Alt.` Отмена удаления
5. Система удаляет все связи модификатора с услугами и связанные настройки.
6. Система удаляет модификатор и его значения.

Критерии приемки: все связи модификатора с услугами и связанные настройки удалены; связанные услуги сохранены; модификатор и его значения удалены из системы; модификатор недоступен для добавления к услугам.

**Отмена удаления:**

1. Администратор отменяет удаление.
2. Система оставляет модификатор услуги без изменений.
3. Возврат к пункту №з **основного сценария**

Критерии приемки: модификатор не удален.

# Сущности
## Модификатор услуги

Модификатор услуги - это сущность, которая используется для выбора одного\нескольких значений из множества значений.

Модификаторы создаются администратором в панели. Каждому модификатору назначается N число значений.

## Значение модификатора услуги

Используется как значение модификатора.
